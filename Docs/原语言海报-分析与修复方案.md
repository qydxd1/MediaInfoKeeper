# 「优先原语言海报」导致媒体库首选语言失效：分析与修复方案

> 状态：分析 + 已按 §9 的确认规则实施（`Patch/MetaData/OriginalPoster.cs`），`net8.0`/`net6.0` 编译通过（见 §7.2）；尚未在真实 Emby 实例上做功能验证。目标 Emby 版本：`4.10.0.40`（`Version.json` 限定 `4.10.0.40`–`4.10.99.99`）。
> 涉及文件：`Patch/MetaData/OriginalPoster.cs`、`Options/MetaDataOptions.cs`、`Patch/PatchManager.cs`。

## 1. 结论摘要

- 现象：开启「优先原语言海报」后，媒体库设置的首选语言（首选图片语言 / 首选元数据语言）在远程图片里"失效"——首选语言的图片被过滤掉，自动刮削也改为下载原语言图片。
- 根因：`OriginalPoster` 的 Harmony Prefix 把 `RemoteImageQuery.IncludeAllLanguages` 设为 `false`，并把 `LibraryOptions.PreferredImageLanguage` 临时改成作品原语言。Emby 4.10 会据此做**硬过滤**，只保留「原语言 + 无语言 + en」的图片。
- 这不是排序问题：过滤发生在 `ProviderManager.GetAvailableRemoteImages` 内部、排序之前，仅调整顺序无法把被过滤的图片找回来。
- 修复方向：保留原语言优先，但让库首选语言重新进入结果集。把临时 `PreferredImageLanguage` 从「单个原语言」改成有序语言集合——Emby 自身用 `GetConfiguredLanguages` 按逗号拆分，并按集合顺序排名。最终规则见 §9：**库首选语言含中文时中文排第一、原语言第二；不含中文时原语言排第一**。

## 2. 现有实现（v1.7.5.6-beta.1 / `a286a48`）

`Patch/MetaData/OriginalPoster.cs:189-202`：

```csharp
[HarmonyPrefix]
private static void GetAvailableRemoteImagesPrefix(BaseItem item, ref LibraryOptions libraryOptions,
    ref RemoteImageQuery query, CancellationToken cancellationToken) {
    if (!isEnabled || item == null || libraryOptions == null || query == null) return;

    var originalLanguage = GetOriginalLanguage(item, cancellationToken);
    if (string.IsNullOrWhiteSpace(originalLanguage)) return;

    query.IncludeAllLanguages = false;
    libraryOptions = CopyLibraryOptions(libraryOptions);
    libraryOptions.PreferredImageLanguage = originalLanguage;
    ...
}
```

- 原语言来源：反射调用 MovieDb 插件 `MovieDbProvider.Current.EnsureMovieInfo(tmdbId, true, null, ct)` / `MovieDbSeriesProvider.Current.EnsureSeriesInfo(tmdbId, null, ct)`，取 `original_language`（电影）或 `languages[0]`（剧集）；季/集用所属剧集的 TMDb id（`dae27ae`）。
- `NormalizeLanguage` 会把 `cn` 归一为 `zh` 并去掉地区后缀（`5b58660`）。
- 该 Prefix 同时挂在 `ProviderManager.GetAvailableRemoteImages` 的 4 参（UI/服务调用）与 5 参（内部刷新，带 `IDirectoryService`）重载上（`OriginalPoster.cs:66-107`）。
- 这个"硬覆盖"写法由 `0c17499`（1.7.5.x）引入，替代了 `d67d499` 的"取全集后稳定重排"实现（旧排序方案见 2.1）。

### 2.1 旧实现（`0c17499` 之前）

Prefix 只做 `query.IncludeAllLanguages = true`，不动 `PreferredImageLanguage`；Postfix 再按「原语言 0 分 / 库首选语言 1 分 / 其它 2 分」稳定重排返回列表。旧实现不会让任何语言消失，但也会把库里所有语言的图片都返回（包括 en/无语言），并让原语言排在最前面。

### 3.3 首选图片语言的回退链（`BaseItem.410.cs:2434-2455`）

```csharp
public string GetPreferredImageLanguage(LibraryOptions libraryOptions) {
    string text = PreferredMetadataLanguage;                 // 1. 条目自身覆盖
    if (string.IsNullOrEmpty(text) && ExtraType 是 AdditionalPart)

```

- 插件覆盖 `libraryOptions.PreferredImageLanguage` 会直接截断第 3 步之后的回退，库元数据语言/服务器全局配置都不再参与。
- 只要第 3 步非空，第 4、5 步就被跳过——这也是"库首选语言失效"的直接机制。
- 注意：该方法在 4.10 才有；插件引用的是 `MediaBrowser.Server.Core 4.9.1.90`，编译期不可直接调用，需要反射或自行复刻回退链。

### 3.4 自动刮削的选图顺序（`ItemImageProvider.410.cs:238-251, 346-385`）

- `RefreshFromProvider` 构造 `RemoteImageQuery { ProviderName = provider.Name, IncludeAllLanguages = false, IncludeDisabledProviders = false }`，再对每种图片调用 `DownloadImage(item, ..., list, minWidth, type, ct)`。
- `DownloadImage` 遍历 `images`（顺序即 `ProviderManager` 返回顺序），取**第一个**类型匹配且宽度达标的图片下载；仅 `404` 继续尝试下一张，其它 `HttpException` 直接 `break`。
- 因此返回顺序 = 自动刮削结果。原语言排第一，自动刮削就必选原语言海报。

### 3.6 上游 MovieDb 图片 provider 不做语言过滤

`MovieDbImageProvider.410.cs` 的 `GetImages(RemoteImageFetchOptions, ct)` 返回该条目所有语言的图片（`iso_639_1` 为 `xx` 时置空），过滤完全在 `ProviderManager` 侧完成。因此插件只需控制 `ProviderManager` 的入参即可。

## 4. 根因拆解

1. **硬过滤**：`IncludeAllLanguages=false` + 临时 `PreferredImageLanguage=原语言` → `preferredImageLanguages = [原语言, en]`，库首选语言（如 zh）的图片被 `Where` 丢弃。
2. **回退链被截断**：库只设了"首选元数据语言"、没设"首选图片语言"时，本来会走第 4 步；插件写入 `PreferredImageLanguage` 后该值非空，第 4/5 步失效。
3. **顺序决定自动选图**：`DownloadImage` 取第一张，所以即便库首选语言图片还在，只要原语言排前面，自动刮削仍用原语言——用户感知就是"首选语言没用"。

## 5. 修复方案候选

> 最终采用 **B 的扩展版**（见 §9）：仍走并集放行，但集合顺序按"库首选语言是否含中文"决定，而不是固定 `"原语言,库首选语言"`。

| 方案 | 做法 | 结果 | 代价/风险 |
| --- | --- | --- | --- |
| A：全集 + 重排（回到 `d67d499`） | Prefix `IncludeAllLanguages=true`，Postfix 稳定排序（原语言第一，其余保持原生顺序） | 原生首选语言图片不再被过滤；原语言置顶 | 返回集合变大（含 en/无语言/其它语言），前端分页 `Limit` 可能把后面的图挤掉；Postfix 需等待 `Task`（旧实现用 `ContinueWith`/`GetAwaiter`） |
| **B：并集放行 + 原语言置顶（推荐）** | Prefix 保持 `IncludeAllLanguages=false`，把 `PreferredImageLanguage` 设为 `"原语言,库首选语言"` | 过滤集合 = {原语言, 库首选语言, en, 无语言}；排序时原语言 idx=0 排最前，库首选语言 idx=1 紧随 | 依赖 Emby 用逗号拆分该字段（`GetConfiguredLanguages`）；需自行复刻"等效首选图片语言" |
| C：只影响手动浏览 | 用 `IncludeDisabledProviders`/`ProviderName` 区分手动与自动；自动刷新完全不覆盖 | 自动刮削永远遵循库首选语言；手动浏览里原语言置顶 | 语义变为"仅浏览时优先"，与原功能描述不完全一致；判别字段依赖 Emby 实现细节 |
| D：仅在库无首选语言时覆盖 | `GetPreferredImageLanguage` 非空则直接放行 | 库配置优先，无配置时用原语言兜底 | 等价于"功能基本不生效"，与"优先原语言海报"诉求冲突 |

补充：方案 B 与 A 的差别在于"是否保留原生过滤语义"。B 不扩大结果集（只多放行库首选语言），不会破坏前端 `Limit` 分页；且不需要 Postfix，改动最小。

## 6. 推荐方案 B 的实现设计

### 6.1 关键点

- 临时 `PreferredImageLanguage` 允许多值：Emby 用 `_localizationManager.GetConfiguredLanguages(value)` 拆分（按 `,`），对每个条目做 `FindLanguageInfo`。传入 `"ko,zh"` 时 `preferredImageLanguages = [ko, zh, en]`。
- 排序权重按集合下标递减，`ko`（idx 0）排在 `zh`（idx 1）之前，`en` 最后。原语言仍第一，天然满足功能预期；库首选语言不再丢失。
- `en` 由 `NormalizeLanguages` 自动追加，插件无需手动加入。
- 该字段只改本地副本 `LibraryOptions`，不写回库配置（`CopyLibraryOptions` 已存在）。

### 6.2 需要"等效首选图片语言"的原因

库通常只设"首选元数据语言"（`libraryOptions.PreferredMetadataLanguage`），而 `libraryOptions.PreferredImageLanguage` 为空。若插件只把原语言写进去，就截断了原生回退（见 3.3）。因此需要在 Prefix 里取到 Emby 本来会用的值：

1. 反射调用 `item.GetPreferredImageLanguage(libraryOptions)`（4.10 存在，public，精确签名 `(LibraryOptions) -> string`）；用 `PatchMethodResolver` 不适用（非补丁目标），可用 `GetMethod(name, BindingFlags.Instance|Public, null, new[]{typeof(LibraryOptions)}, null)` 精确取，缺失则回退第 2 步。
2. 回退：`item.GetPreferredMetadataLanguage(libraryOptions)`（4.9 编译期 API 已存在，与 4.10 第 3–5 步等价）。
3. 把结果按 `,` 拆分、`Trim`、去空、去重、小写化。

### 6.3 代码草案

```csharp
[HarmonyPrefix]
private static void GetAvailableRemoteImagesPrefix(BaseItem item, ref LibraryOptions libraryOptions,
    ref RemoteImageQuery query, CancellationToken cancellationToken) {
    if (!isEnabled || item == null || libraryOptions == null || query == null) return;

    var originalLanguage = GetOriginalLanguage(item, cancellationToken);
    if (string.IsNullOrWhiteSpace(originalLanguage)) return;

    query.IncludeAllLanguages = false;
    libraryOptions = CopyLibraryOptions(libraryOptions);
    libraryOptions.PreferredImageLanguage = BuildPreferredImageLanguages(item, libraryOptions, originalLanguage);
    ...
}

// 原语言排最前，其后是库的等效首选图片语言（保持原生顺序），去重后逗号拼接
private static string BuildPreferredImageLanguages(BaseItem item, LibraryOptions libraryOptions, string originalLanguage) {
    var languages = new List<string> { originalLanguage };
    foreach (var language in GetLibraryPreferredImageLanguages(item, libraryOptions)) {
        if (!languages.Any(existing => string.Equals(existing, language, StringComparison.OrdinalIgnoreCase)))
            languages.Add(language);
    }
    return string.Join(",", languages);
}

private static IEnumerable<string> GetLibraryPreferredImageLanguages(BaseItem item, LibraryOptions libraryOptions) {
    var configured = GetPreferredImageLanguage(item, libraryOptions)   // 反射；null 表示 4.9 或解析失败
                     ?? item.GetPreferredMetadataLanguage(libraryOptions); // 编译期 API，等价 4.10 回退链
    if (string.IsNullOrWhiteSpace(configured)) yield break;

    foreach (var part in configured.Split(',')) {
        var value = part.Trim();
        if (value.Length != 0) yield return value;
    }
}

private static string GetPreferredImageLanguage(BaseItem item, LibraryOptions libraryOptions) {
    var method = item.GetType().GetMethod("GetPreferredImageLanguage",
        BindingFlags.Instance | BindingFlags.Public, null, new[] { typeof(LibraryOptions) }, null);
    return method?.Invoke(item, new object[] { libraryOptions }) as string;
}

private static string NormalizeLanguage(string language) { ... 现有实现，cn -> zh、去地区 ... }
```

注意：`CopyLibraryOptions` 必须用**修改前**的 `libraryOptions` 计算库首选语言，代码里先调用 `GetLibraryPreferredImageLanguages` 再覆盖即可；上面草案中 `BuildPreferredImageLanguages` 接收的 `libraryOptions` 是副本，`PreferredImageLanguage` 尚未赋值，因此读到的仍是库原值——顺序不要写反。

若 `item.GetPreferredMetadataLanguage(LibraryOptions)` 在 4.9 的 `MediaBrowser.Server.Core 4.9.1.90` 中不可编译，回退为 `libraryOptions.PreferredMetadataLanguage`（`LibraryOptions` 字段在 4.9 已存在），此时"服务器全局语言"一层会缺失，功能上仅影响未配置库语言的极端场景。

### 6.4 与现有逻辑的兼容

- `GetOriginalLanguage` 的 TMDb 解析、季/集用剧集 id、`NormalizeLanguage(cn→zh)` 全部不变。
- 功能关闭（`isEnabled=false`）时 Prefix 直接返回，行为与原生完全一致。
- 库没有配置任何首选语言（罕见）时集合退化为 `[原语言]`，行为等同于当前版本。
- 无需 Postfix；不引入异步等待，不改变返回集合规模。

## 8. 待确认（已被 §9 的确认结论取代）

1. 「优先原语言海报」的语义：是"自动刮削也优先原语言、但库首选语言图片不能消失"（方案 B），还是"只有手动浏览时优先，自动刮削始终遵循库首选语言"（方案 C）？
2. 库同时配置了首选图片语言与首选元数据语言时，放行顺序是否以首选图片语言为准？（方案 B 默认：`GetPreferredImageLanguage` 的返回值即原生优先级）
3. 是否需要同时支持 `IncludeAllLanguages=true` 的手动勾选？方案 B 下 Prefix 仍会强制 `false`，用户勾选"所有语言"时是否也应放行全部？建议：`query.IncludeAllLanguages` 为 `true` 时直接跳过 Prefix（尊重用户显式选择）。

## 9. 最终确认的规则（实施版）

用户确认的语义（2026-10-20）：

1. **库首选语言含中文**（`zh`、`zh-CN`、`zh-TW`、`zh-HK`、`cn` 都算中文）→ 中文海报优先；中文海报缺失时自动回退到原语言；原语言海报仍保留可见，排在中文之后。
2. **库首选语言不含中文** → 原语言海报优先，其余库首选语言图片保留可见（不丢图）。
3. 自动刮削沿用同一顺序（`DownloadImage` 取第一张），因此：中文库有中文图时选中文、无中文图时选原语言；非中文库选原语言。
4. 手动勾选"所有语言"时不再强制关闭过滤：Prefix 只设置首选语言集合（影响排序），是否过滤由 Emby 按用户勾选决定。

### 9.1 实现方式

`GetAvailableRemoteImagesPrefix` 不再写 `query.IncludeAllLanguages = false`，改为计算"原语言 + 库等效首选图片语言"的有序集合写入 `LibraryOptions` 副本：

- 含中文：`[中文项…, 原语言, 其余语言…]`
- 不含中文：`[原语言, 其余语言…]`

Emby 侧排序权重 `2 + (len - idx)`（`OrderByDescending`）保证集合首项最靠前；`en` 由 `NormalizeLanguages` 自动补齐；过滤仍走原生 `Where`，所以只放行"原语言 ∪ 库首选语言 ∪ en ∪ 无语言"。
